# ADR-0003: パネルのレイアウトと最小サイズ

| 項目 | 値 |
|------|----|
| Status | **Accepted** |
| Date | 2026-09-27 |
| Binds | instant-translate |
| Decision makers | nlink-jp maintainers |
| Triggered by | ADR-0002 を最大の文字サイズで確かめたとき、パネルを縮めるとレイアウトが崩れた — 標準の大きさでも同じ。PR #1（@anonymousaga）も同じ行を「窮屈」と報告していた |

## 背景

パネルの最小サイズは 320 × 320pt の固定値だった。入力欄の下の行 — 入力言語ピッカー、
「(言語)」ヒント、矢印、訳先ピッカー、ヒント、Translate — はそれより広い幅を要る。
メニュー型のピッカーはいちばん長い言語名の幅になるので、320pt ではピッカー 2 つだけで
行が埋まる。残りはヒントに回り、ヒントは 1 文字ずつ折り返され、行が縦に伸び、Translate
ボタンは細い帯になり、Copy / Quit の行はパネルの外へ押し出された。この行は文字サイズを
見ていないので、ADR-0002 ではなく v0.3.1 の不具合。

必要な幅は定数ではない: いちばん長い言語名、つまり OS の言語と Translation framework が
提供する言語に左右される。必要な高さは、失敗メッセージが出ると増える。

## 決定

### 決定 1: ヒントはピッカーの下に置く

各ピッカーの下に、caption 1 行分の空行を置き、ヒントはその行に重ねる。重ねたヒントには
ピッカーの幅が提示されるので、行の幅を増やさない。それより長い名前は中央を省略し、両端の
括弧（選択ではなくヒントであることを示す）を残す。ヒントが無いときも空行はあるので、行の
高さは変わらない。ヒントと状態表示の行のあいだには、約半行の固定の空きを置く。

ピッカー、矢印、ボタンは縮まないので、行の最小幅はそれらだけで決まり、判定された言語が
変わっても変わらない。

### 決定 2: パネルの最小サイズは、並べた結果から測る

`PanelView` が並べた大きさを報告し（`onGeometryChange`）、純関数
`PanelMinimumSize.compute` が最小を求める:

- **高さ** = 中身の高さ − 2 つの文字欄がそれぞれ最小 80pt を超えて伸びている分 +
  タイトルバーの余白
- **幅** = 入力言語ピッカー + 矢印 + 訳先ピッカー + ボタン + 間隔 + 余白

中身はパネルいっぱいに広げる frame より手前で測るので、パネルが小さすぎるときは、
与えられた高さではなく必要な高さを報告する。ほかに現れるもの — 失敗メッセージ — は
自動的に含まれる。`AppController.setPanelMinimum` がそれを `contentMinSize` として
次のランループで適用し、画面の大きさを上限とし、パネルが小さければ（上端をメニューバー
項目の下に保ったまま）広げる。

### 決定 3: ホスティングビューにはウィンドウの大きさを管理させない

`NSHostingView` は `sizingOptions = []` とし、ウィンドウの `contentView` にせず、
ただのコンテナビューの中に置く。

## 結果

- OS の言語や文字サイズによらず、パネルを崩れるところまで縮められなくなった。最小幅は
  いちばん長い言語名で決まり、メンテナの環境（日本語 UI）では開発中に 560〜574pt を観測した。
- 最小まで縮めたパネルに失敗メッセージが出ると、切れずにパネルが広がる。
- この行は、旧来の 1 行の形より caption 1 行分高い。
- パネルの中で伸びるビューは、すべて `compute` で差し引かなければならない。差し引かない
  ものを足すと、最小がパネルとともに大きくなる（A5 参照）。

## 検討した代替案

**A1. 固定の最小値を大きくする。** いちばん簡単。不採用: 必要な幅は言語名に従い、言語名は
OS の言語と framework の言語一覧で変わるので、どんな定数もどこかで間違う。

**A2. `NSHostingView` に最小を報告させる（`sizingOptions: .minSize`、既定にも含まれる）。**
試した。この設定は幅 0・高さ 0 の提示で測るが、文字はそれに正直に答えられない: 高さを
固定しない 1 行の文字は高さ 0 を返し（最小が 16〜29pt 足りず、下の余白が削られた）、
本来の高さに固定した文字は 1 文字ずつ折り返す（最小が 646pt に跳ね上がった）。複数行の
失敗メッセージは、そもそも正直に答えさせる方法が無い。

**A3. ヒントをピッカーの横に置いたまま、いちばん長いヒントの幅を確保する。** ヒントが
変わってもパネルは広がらなくなるが、ピッカーに加えていちばん長い名前をさらに 2 回分
確保するので、最小幅が 863pt に達した。

**A4. 行の幅が足りればヒントを横、足りなければ下にする。** 作ってみてメンテナが取りやめた:
段組みが切り替わるときに操作部品がずれ（Translate ボタンが縦に動く）、違和感があった。
切り替えは入力で行き来しないよう、いちばん長くなりうるヒントで判定し、最小の高さも
両方の段組みで同じにしていたが、ずれは残った。

**A5. 行の幅から `Spacer` の幅を引いて測る。** 暴走して取りやめた: 測定用の修飾子で
包んだ `Spacer` はスタックの spacer ではなくなり、縦にも伸びる。行が縦の余りを吸い込み、
`compute` はそれを差し引かないので、パネルを最小まで広げると最小がまた大きくなり、画面の
高さまで達した。今はボタンを frame で右へ寄せ、ピッカーとボタンを直接測っている。

**A6. `NSHostingView` をウィンドウの `contentView` のまま `sizingOptions = []` にする。**
起動時に落ちた: `contentView` のときは `windowDidLayout` でウィンドウの大きさを変え続け
（`updateAnimatedWindowSize`）、レイアウト処理の中で測った最小とぶつかり、AppKit が例外を
投げた（「更新が終わらない」）。ただのコンテナビューに入れると、ホスティングビューは
ウィンドウの大きさの管理から完全に外れる。
